# 星火智援功能边界讨论稿

这份清单只用来讨论“系统到底要做哪些功能、每个功能做到什么程度”。大家逐项看，觉得合理就保留，觉得三周内做不完就缩小或删除。

## 1. 研究区地图

系统仍然使用 Cesium 三维地球，但所有业务数据只覆盖一个小型研究区。

我们准备做到：

- 首页可以看到完整地球，并自动飞到研究区。
- 进入功能页面后，镜头主要停留在研究区。
- 地图显示研究区边界和卫星观测覆盖范围。
- 研究区内显示道路、居民点、水源、避难点和消防资源。

不准备做到：制作全国范围的业务数据，或者同时支持多个完全不同的研究区。

- [ ] 保留这个功能
- [ ] 研究区沿用现有木里县示范区域
- [ ] 需要调整：`________________________________`

## 2. 模拟卫星观测数据

系统不是直接随机生成一个火点坐标，而是生成或加载一份卫星观测数据，让后续算法自己寻找异常区域。

我们准备做到：

- 卫星数据只覆盖研究区。
- 数据包含正常背景、火情异常、随机噪声和少量干扰。
- 可以重新生成数据，也可以加载一份固定演示数据。
- 固定演示数据保证课堂展示时能够稳定识别火情。

三周内不做完整的真实卫星数据生产流程，例如复杂的大气校正和云处理。

- [ ] 保留这个功能
- [ ] 优先使用较容易实现的模拟栅格数据
- [ ] 希望直接制作模拟 GeoTIFF
- [ ] 先做两个小样再决定

## 3. 卫星疑似火点识别

算法读取卫星观测数据，根据温度、光谱或其他异常值寻找疑似火区，而不是读取模拟器保存的答案。

我们准备做到：

- 找出异常像元。
- 过滤零散噪点。
- 将相邻异常像元合并成疑似火区。
- 计算疑似火区中心位置、范围和置信度。
- 在 Cesium 中显示异常像元、疑似火区和候选火点。

三周内不训练新的遥感识别模型，主要使用可解释的规则和空间算法。

- [ ] 保留这个功能
- [ ] 地图需要同时展示异常像元和疑似火区
- [ ] 地图只展示最终疑似火区，减少画面复杂度

## 4. 传感器监测

研究区内布置一组模拟传感器，用于验证卫星疑似火区附近是否真的存在温度、烟雾等异常。

我们准备做到：

- 地图显示传感器位置和工作状态。
- 传感器持续产生温度、烟雾、湿度等数据。
- 不同传感器出现不同程度的异常、延迟或噪声。
- 系统识别异常传感器，并判断是否支持卫星发现。

不连接真实传感器硬件。

- [ ] 保留这个功能
- [ ] 需要展示传感器实时变化图表
- [ ] 只展示当前数值和异常状态即可

## 5. MQTT/EMQX实时消息

传感器数据虽然是模拟的，但发送和接收过程使用真实的 MQTT 消息链路。

我们准备做到：

- 模拟程序通过 MQTT 定时发送传感器数据。
- EMQX 接收并转发消息。
- 后端订阅消息并保存到数据库。
- 前端能够看到新的传感器数据和告警。

不考虑大量设备并发、硬件管理和生产级消息安全。

- [ ] 保留这个功能
- [ ] 前端需要表现出数据持续进入系统的效果

## 6. Node-RED事件流

Node-RED 用来展示传感器数据从接收到形成告警的处理过程。

我们准备做到：

- 接收 MQTT 消息。
- 判断温度或烟雾是否异常。
- 将异常消息转给 8200 后端。
- 保留一张清晰的 Node-RED 流程图用于课程展示。

不把所有业务逻辑都搬到 Node-RED，核心事件和决策仍由后端负责。

- [ ] 保留这个功能
- [ ] Node-RED 只处理传感器告警
- [ ] 希望再加入人工上报或其他简单流程

## 7. 无人机核查

卫星发现疑似火情后，系统生成无人机核查任务。无人机不是真实飞行，而是返回一份模拟影像或处理结果。

我们准备做到：

- 地图显示无人机和目标区域。
- 系统生成核查任务，包括目标、优先级和任务状态。
- 无人机返回是否发现火焰或烟雾、位置和置信度。
- 无人机结果用于修正卫星疑似火点。

不接真实无人机、真实视频流或飞控系统。

- [ ] 保留这个功能
- [ ] 使用无人机样例图片进行识别
- [ ] 使用处理后的模拟检测结果
- [ ] 两种方式都保留

## 8. Qwen-VL图像分析

Qwen-VL 用来分析一张卫星或无人机样例图，给出是否存在火焰、烟羽及文字说明。

我们准备做到：

- 用户选择或上传一张样例图片。
- Qwen-VL 返回火情判断、置信度和简短解释。
- 结果作为卫星或无人机的一条证据保存。
- 前端能够查看原图和识别结论。

不训练或微调模型，也不承诺精确分割每一条火线。

- [ ] 保留这个功能
- [ ] 主要用于无人机核查
- [ ] 主要用于卫星图像解释

## 9. 多源证据融合

系统综合卫星、传感器和无人机结果，判断火情是否可信，并给出最终可信火点。

我们准备做到：

- 分别显示三类证据是否支持火情。
- 根据来源可靠性和识别置信度计算融合结果。
- 证据不足时保持“疑似”状态。
- 多类证据一致后变为“已确认”。
- 输出可信火点、可信范围、总置信度和判断原因。
- 如果证据矛盾，显示警告，不强行确认。

不追求复杂科研级融合模型，重点是过程清楚、结果可解释。

- [ ] 保留这个功能
- [ ] 三类证据全部一致才确认
- [ ] 两类独立证据一致即可确认，第三类继续补充

## 10. 火情事件和时间线

系统需要把一次火灾从发现到处置的过程串在同一个事件里。

我们准备做到：

- 创建一次监测事件，但创建时没有最终火点。
- 依次记录卫星发现、传感器告警、无人机核查、融合确认、推演和决策。
- 用户可以查看事件当前状态和完整时间线。
- 事件结束后可以关闭并保留历史结果。

不建设复杂的多部门工单和审批系统。

- [ ] 保留这个功能
- [ ] 需要提供简单历史事件列表
- [ ] 三周内只完整保存当前演示事件

## 11. ForeFire火势推演

可信火点生成后，系统将位置和环境参数交给 ForeFire，计算火势随时间的变化。

我们准备做到：

- 展示多个时间步的火场范围。
- 可以播放、暂停或拖动时间查看火势发展。
- 显示过火面积、蔓延方向和风险等级。
- 明确标记结果来自真实 ForeFire 还是备用演示结果。

不进行真实消防业务级的模型校准。

- [ ] 保留这个功能
- [ ] 需要火势时间播放效果
- [ ] 只切换几个固定时间节点即可

## 12. 空间影响分析

系统利用 PostGIS 判断火势可能影响哪些居民点、道路和重要目标。

我们准备做到：

- 统计受影响居民点和人口。
- 找出可能被火场覆盖或切断的道路。
- 判断重点保护目标是否处于危险范围。
- 在地图上高亮受影响对象。

不做全国尺度分析，也不做精确人员伤亡预测。

- [ ] 保留这个功能
- [ ] 居民点和道路是必须分析对象
- [ ] 还希望加入：`________________________________`

## 13. 救援和疏散路线

系统根据道路、坡度、火势范围和危险区域生成一条或多条路线。

我们准备做到：

- 至少生成一条救援进入路线或人员疏散路线。
- 路线避开当前火场和明显危险区域。
- 显示路线长度、预计时间和风险说明。
- 地图展示推荐路线和备选路线。

不接真实导航和实时交通系统。

- [ ] 保留这个功能
- [ ] 优先做救援进入路线
- [ ] 优先做人员疏散路线
- [ ] 两种路线都做

## 14. 救援资源推荐

系统从数据库中的消防站、人员、车辆、水源和无人机资源里选择适合当前事件的资源。

我们准备做到：

- 查询火点附近可用资源。
- 根据距离、状态和数量生成推荐。
- 显示资源从哪里出发、执行什么任务。
- 资源推荐和路线结果能够对应。

不做生产级排班、采购和跨部门资源管理。

- [ ] 保留这个功能
- [ ] 推荐结果需要允许用户调整
- [ ] 三周内只展示系统推荐结果

## 15. 四个Agent辅助决策

Agent 用来汇总已有数据和算法结果，不代替卫星识别、空间分析和路径计算。

建议设置：

- 环境态势 Agent：解释天气、地形和植被风险。
- 火势风险 Agent：解释 ForeFire 结果和威胁方向。
- 路径资源 Agent：整理路线和资源建议。
- 指挥协调 Agent：汇总其他结果并形成最终方案。

我们准备做到：每个 Agent 都能看到自己的输入、输出和使用了哪些系统结果。

不让 Agent 凭空编造坐标、路线、资源和受灾数字。

- [ ] 保留四个 Agent
- [ ] 如果时间紧，减少为三个，合并的角色是：`____________`

## 16. 人工确认

系统给出的路线、资源和指挥方案只是建议，需要操作人员确认后才能进入“已批准”状态。

我们准备做到：

- 用户可以批准或驳回方案。
- 驳回时可以填写简短原因。
- 操作结果进入事件时间线。

不建设多级审批和复杂权限系统。

- [ ] 保留这个功能

## 17. 任务反馈

被批准的无人机、路线和资源建议转为简单任务，并记录执行状态。

我们准备做到：

- 任务具有待执行、执行中、已完成三种状态。
- 用户可以手动更新状态。
- 首页或指挥页面显示简单数量统计。

不做真实设备回传和复杂绩效统计。

- [ ] 保留简单任务反馈
- [ ] 如果时间紧，只保留任务状态，不做统计图表

## 18. 灾后评估

系统根据最终火场范围与居民点、道路、植被或土地利用数据进行叠加统计。

我们准备做到：

- 计算过火面积。
- 统计受影响居民点和道路。
- 统计不同植被或土地利用类型的过火面积。
- 给出简单灾损等级和说明。

不做精确经济损失、伤亡和生态恢复预测。

- [ ] 保留这个功能
- [ ] 经济损失只做非常明确的教学估算并标注假设
- [ ] 完全不展示经济金额

## 19. 报告和专题图

系统把事件全过程和重要地图结果整理成课程成果。

我们准备做到：

- 生成可以下载的事件报告。
- 报告包含证据、可信火点、火势、影响、路线、资源和决策。
- 导出火势范围、路线资源、灾损评估等核心专题图。
- 报告中的数字尽量来自数据库和算法结果。
