**应急路径规划 Agent 对接说明**
前端需要在“应急路径规划”页面实现基于 Agent 返回结果的路线可视化与交互。请后端 Agent 在完成 ForeFire 蔓延预测分析后，生成一个完整的 `route_package`，用于前端加载关键点、三条路径、风险等级、距离耗时和高程剖面。

**业务目标**
Agent 需要根据以下数据完成路径规划：

- ForeFire 火势蔓延预测结果：火线 GeoJSON、各时刻过火区域、最终火场范围。
- 气象风场数据：风速、风向、风场时序，重点考虑下风向风险。
- 地形 DEM：坡度、海拔、山谷、山脊、陡坡区域。
- 燃料/植被数据：高可燃区域应提高通行风险。
- 起终点：
  - 高风险目标入口点
  - 南侧安全集结点
- 可选：道路、林道、防火通道、河谷线等通行网络数据。

**需要实现的功能**
1. 生成两个点图层数据：
   - `entry_point`：高风险目标入口点。
   - `assembly_point`：南侧安全集结点。

2. 生成三条路线：
   - `main_evacuation`：主疏散路线，优先给人员撤离使用，尽量低风险、时间短。
   - `fire_rescue_approach`：消防救援接近路线，优先靠近火场但避开高风险火线和强风下风向。
   - `safe_route`：安全路径，优先风险最低，可以牺牲距离和耗时。

3. 每条路线需要返回：
   - 路线名称
   - 路线类型
   - 风险等级：`low` / `medium` / `high`
   - 距离，单位 km
   - 预计耗时，单位 min
   - 路线坐标数组
   - 高程剖面数组
   - 路线规划理由
   - 风险说明
   - 是否推荐

4. 前端会根据返回结果：
   - 在 Cesium map 上绘制两个关键点。
   - 在 map 上绘制三条不同颜色路线。
   - 点击左侧路线卡片时高亮对应路线。
   - 根据 `elevation_profile` 绘制高程剖面图。

**字段要求**
- 坐标统一使用 WGS84 经纬度，格式为 `[longitude, latitude]`。
- `coordinates` 必须按路线行进顺序排列。
- `elevation_profile.distance_km` 必须从 0 开始递增。
- `risk` 使用英文枚举：
  - `low`
  - `medium`
  - `high`
- 前端会根据 `risk` 做颜色和标签逻辑。
- 文案字段如 `name`、`reason`、`risk_summary`、`summary` 请直接返回中文。


**后端实现建议**
- 若已有 DEM：对每条路线按固定间距采样 DEM，生成 `elevation_profile`。
- 若有道路/林道数据：优先基于路网做 A* / Dijkstra 路径规划。
- 若暂时没有路网：可先基于栅格代价面规划路线，代价由以下因素组成：
  - 距离成本
  - 坡度成本
  - 接近火线成本
  - 下风向风险成本
  - 高燃料区域成本
- 三条路径应使用不同权重：
  - 主疏散路线：低风险 + 短时间。
  - 消防救援接近路线：接近目标 + 可控风险。
  - 安全路径：最低风险优先。

**最小可用版本**
如果后端短期不能完成真实路网规划，至少先返回：
- `entry_point`
- `assembly_point`
- 三条 `route_options`
- 每条路线的 `coordinates`
- 每条路线的 `distance_km`
- 每条路线的 `eta_min`
- 每条路线的 `elevation_profile`

这样前端就可以先完成地图可视化、路线点击高亮和高程剖面联动。
